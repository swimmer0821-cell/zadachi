# CLAUDE.md — «Задачи LAZA» (приложение для сотрудников)

ПУБЛИЧНЫЙ репозиторий: всё здесь видит весь интернет. Ни ПИН-кодов, ни ключей, ни Telegram id сотрудников в файлах быть не должно.

## Что это и кто пользуется
Мобильное приложение (PWA) для команды ООО «SUB-PROFI»: «Мои задачи», постановка задач, задачи команды, проекты, список сотрудников, рассылки в Telegram.
Сотрудник видит и закрывает свои задачи; руководитель ставит задачи, правит проекты и команду, делает рассылки.
Интерфейс на русском и узбекском (латиницей).

## Где работает и как обновляется
- Сайт: GitHub Pages, ветка `main`; изменения появляются через 1–2 минуты.
- Сервер: Google Apps Script «LAZA бот задач — мост» (код моста в этом репозитории НЕ лежит). Адрес — в `index.html`, `CFG.API_URL`; не менять и не копировать в другие файлы.
- Мост связан с ботом задач (`tasks_bot/` в репозитории бота продаж): бот раз в ~20–30 секунд забирает у моста новые задачи и рассылки и доставляет их в Telegram.
- ПРАВИЛО: при каждом изменении `index.html` поднимать версию кэша `CACHE` в `sw.js` (сейчас `zadachi-v3`). Иначе телефоны не обновятся. Отдельного `APP_VER` в этом приложении нет.

## Карта файлов
- `index.html` — всё приложение: вход по ПИН, списки задач, карточка задачи, проекты, команда, рассылка, переводы ru/uz. Настройки — блок `CFG` вверху.
- `sw.js` — офлайн-кэш (сеть в приоритете; запросы к Google не трогает).
- `manifest.webmanifest`, `icons/` — установка на экран телефона.

## Что нельзя ломать
- Вход: сотрудник выбирает имя и вводит ПИН (4–6 цифр), который выдаёт руководитель в «Команде»; сервер возвращает токен, он хранится на телефоне. После нескольких неверных ПИН вход блокируется на 10 минут. При ошибке авторизации приложение выходит на экран входа (`logout`). Не ослаблять.
- Роли: руководитель (`S.me.isManager`) видит все задачи, ставит и удаляет задачи, управляет проектами, командой и рассылками; сотрудник — только свои задачи (`canAct`). Скрытие кнопок в приложении — не защита, настоящая проверка прав делается на мосте; не полагаться на интерфейс.
- Себе нельзя снять права руководителя или поставить «Не работает».
- Статус задачи меняется кнопками, а бот задач присылает уведомления; не менять названия действий (`app_login`, `app_data`, `app_task_save`, `app_status`, `app_broadcast`, `app_staff_save` и др.) без согласованного изменения моста.
- Повтор после обрыва связи (`call` предлагает «Повторить»): в коде приложения не видно номера запроса против дублей для новой задачи и рассылки (в отличие от приложения склада и «Денег»). Не добавлять автоматические повторы, не нажимать «Повторить» вслепую.
- Рассылка отправляется только после явной кнопки «Отправить в Telegram» и только выбранным сотрудникам.
- Тексты на двух языках: новый русский текст добавлять вместе с узбекским переводом.
- Telegram id и ПИН сотрудников не показывать в списках без необходимости и не писать в код.

## Как проверять перед публикацией
1. `python -m http.server 8000`, открыть `http://localhost:8000/` в браузере.
2. Ширина окна 390 px: нет прокрутки вбок, кнопки крупные, ПИН-клавиатура помещается.
3. Консоль браузера — без красных ошибок; переключить ru/uz.
4. Рабочие данные не менять для проверки (не ставить задачи и не делать рассылки сотрудникам) без согласия владельца: сообщения придут людям в Telegram.
5. Поднять `CACHE` в `sw.js`.

## Как откатить
- `git revert <коммит>`, отправить в `main` (снова поднять версию кэша).
- Копия до крупных правок: создать ветку-копию (`git branch backup-<дата>`) перед началом работы.

## Правила работы с владельцем
- Владелец не программист: простыми словами, без терминов, коротко, по шагам.
- Перед любыми изменениями, которые затрагивают задачи сотрудников, рассылки, права и ПИН, — сначала спросить.
- Не коммитить и не пушить без явной просьбы; репозиторий публичный.
- Секреты — только в свойствах скрипта моста и в `.env` бота, не в коде и не в этом файле.
- Нет данных — писать «уточнить» и спрашивать, не выдумывать.
